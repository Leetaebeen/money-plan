# 개인 가계부 첫 구현

## 범위

목표 달성을 중심으로 홈·거래·목표·자산·백업 화면을 추가했다. React·Vite·Dexie를 유지하며 기존 계산기는 별도 메뉴에서 제공한다. 기본 계좌는 월급·고정비·생활비·청약·적금·ISA·연금저축의 역할만 제안하고 잔액은 비워둔다.

## 데이터와 계산

- DB v3: `accounts`, `ledgerEntries`, `ledgerGoals`, `importBatches`, `ledgerMeta` 추가. v1/v2 데이터는 유지한다.
- 시작 잔액은 기준일 00시 금액이다. 이후 실제 거래를 더해 잔액을 구한다. 모르는 잔액은 0으로 취급하지 않는다.
- 거래는 수입·지출·계좌 이동·환불·잔액 조정으로 나눈다. 순소비는 지출에서 환불을 차감하며 이체·잔액 조정은 제외한다.
- 직접 입력 이체는 두 계좌의 같은 날짜·반대 금액 거래로 원자적으로 저장하고 함께 수정·삭제한다. 파일로 가져온 이체는 계좌별 한쪽 기록으로 보존한다.
- 목표는 연결 계좌 전체 잔액을 사용하며 음수 잔액도 차감한다. 계좌를 두 목표에 중복 연결할 수 없다. 아직 등록하지 않은 계좌 잔액이 있으면 금액·도달일을 추정하지 않는다.
- 목표 필요액은 목표 잔액을 오늘 이후 목표일까지 남은 납입 회차로 나눠 원 단위 올림한다. 매월 납입일은 1~28일이다. 월 적립액은 계획값이며 실제 자산에 더하지 않는다. 투자 수익률은 0%다.
- 모든 원화 금액은 정수이며 입력 범위·합계의 안전한 정수 범위를 검증한다.
- 가계부 수정은 전역 리비전을 확인하는 DB 트랜잭션 안에서 검증·반영한다. 오래된 화면의 저장·복원은 실패하며 새로고침을 안내한다.

## 파일과 백업

- UTF-8/EUC-KR CSV 및 TSV 지원. 사용자 요청에 따라 Excel/XLSX 가져오기는 추가하지 않는다. PDF·은행별 양식 변환기는 미구현이다.
- 같은 파일 해시+계좌 조합은 재반영을 막는다. 날짜·금액·설명 기반 중복은 후보이며 사용자가 선택할 수 있다.
- 날짜 오류·미래 거래·기준일 이전 거래·0원·열 불일치·동시 입출금 등을 행 단위로 표시한다. 선택한 정상 행만 일괄 저장한다.
- 가져오기 취소는 해당 묶음의 수정된 거래까지 삭제한다. 원본 파일은 저장하지 않는다.
- 백업은 가계부 네 테이블의 데이터를 PBKDF2-SHA256 210,000회와 AES-256-GCM으로 암호화한다. 파일마다 난수 salt·IV를 사용한다.
- 복원은 인증 복호화와 스키마·관계 검증 후 미리보기를 제공한다. 확인하면 가계부만 원자적으로 교체하며 기존 계산기 이력은 유지한다.
- 백업에서도 계좌 기준일보다 이전 거래와 잘못된 계좌 식별자를 거부한다. 검증 실패 시 현재 가계부는 유지한다.
- 브라우저 내부 데이터는 별도 암호화되지 않는다. 동기화·서버 업로드는 없다.

## 검증

`npm run check`에 기존 테스트와 `apps/web/tests/ledger.test.ts`를 포함한다. 추가 테스트는 입력·달력, 잔액 범위, 목표 납입 회차, 1,000원 미만 목표 마무리, 목표 중복 연결, 이체 보존, CSV 인용/중복/오류, v2 업그레이드, 중복 파일, 원자적 롤백, 저장 충돌, 암호화 백업을 검증한다.

브라우저에서는 합성 계좌·목표 등록, CSV 정상/중복/오류 행 미리보기 및 반영, 암호화 백업 미리보기와 복원을 확인했다. 320px 및 390px 뷰포트를 검사했고 320px의 가로 넘침을 수정했다. 데스크톱의 좁은 뷰포트 검증은 iOS·Android 실기기 검증을 대신하지 않는다.

### 기존 출력 폴더를 보존하는 검증

Windows 실행 환경에서 기존 출력 폴더를 처리하는 동안 빌드 프로세스가 종료되는 현상을 관찰했다. 새 출력 폴더를 사용하면 기본 압축 설정으로 정상 빌드된다. 기존 파일을 삭제할 필요 없이 아래처럼 별도 경로에서 검증할 수 있다. 재실행 시 새 폴더 이름을 사용한다.

```sh
npm run build:pages -- --outDir dist-pages-review
node scripts/check-pwa-build.cjs apps/web/dist-pages-review
node scripts/check-pages-build.cjs apps/web/dist-pages-review
```

검사 스크립트의 경로 인자는 저장소 기준이며 생략하면 기존 `apps/web/dist`를 검사한다. CI의 기본 경로와 압축 설정은 유지한다.

## 후속 구현

급여 주기 지출 예산은 예정 월급일 당일부터 다음 월급 전날까지의 고정비·생활비 계획과 오늘까지 기록한 지출·환불을 비교한다. 같은 계좌는 예산과 거래를 한 번만 합산하며, 별도 생활비 계좌에는 오늘을 포함한 남은 일수로 나눈 하루 기준액을 표시한다. 예산 초과는 숨기지 않고 하루 기준액은 0원으로 표시한다. 주기 중간에 기록을 시작한 계좌는 남은 예산을 확정하지 않는다. 잔액을 몰라도 전체 주기 거래 기록이 있으면 예산 비교는 가능하다. 환불은 수령일 주기에 반영하며 이전 소비와 자동 연결하지 않는다. 이는 현금 가용액이 아니며 예정 지출, 기록 누락, 다른 계좌 결제, 급여 입금 여부, 휴일 급여 조정은 반영하지 않는다. 계획 저장은 거래를 만들지 않는다.

월급 화면의 월 저축 실적은 현재 배분 계획과 조회 월에 기록된 계좌 이동의 순액을 비교한다. 초기 잔액·수입·평가손익은 제외하고, 출금은 실적을 줄이며 저축계좌 간 이동은 전체 합계에서 상쇄한다. 계좌별·목표별 부족액은 별도로 계산한다. 연결되지 않은 파일 이체가 있거나 계좌 기준일이 월 중간 이후이면 부족액은 미확정으로 표시한다. 실제 거래 누락 여부까지 확인하는 기능은 아니며, 과거 월을 조회해도 현재 계획과 비교한다. 과거 계획 이력과 파일 이체의 상대 거래 연결은 후속 범위다.

CSV/TSV 가져오기는 제목 행 선택, 구분자 자동 감지·직접 지정, 양수 금액+입출금 구분 열을 지원한다. YYYYMMDD·점/슬래시 구분 날짜·한국어 날짜를 정규화하며 잘못된 일자와 시간·알 수 없는 입출금 구분·음수 방향 금액은 오류로 표시한다. 안내문·빈 행·인용된 여러 줄 내용 이후에도 미리보기의 행 번호는 원본의 실제 시작 줄을 가리킨다. 제목 선택은 처음 50개 행, 파일은 안내·빈 행 포함 5,050개 레코드, 거래는 5,000개, 열은 100개까지 허용한다. 실제 은행 파일로 검증한 전용 변환기는 아니며 XLSX/PDF 지원은 포함하지 않는다.

실제 은행 파일에 맞춘 변환기, 신용카드 구매·청구 정산 연결, 예정 지출과 실제 급여 주기별 가용액, 적금 만기와 ISA·연금 납입 관리, 정확한 부채/순자산 원장이 다음 단계다. 현재 금융자산 합계를 순자산이나 즉시 사용 가능한 돈으로 표시하지 않는다.

## 월급 배분 계획

- 월급 화면에 실수령액·급여일·고정비·생활비·매달 남길 예비비와 계좌별 저축·투자 배분액을 저장한다. 예비비는 이번 월급에서 남길 금액이며 이미 모은 비상금이 아니다.
- 배분 가능액 = 실수령액 - 고정비 - 생활비 - 예비비. 잔여액 = 배분 가능액 - 저축·투자 배분. 음수는 부족액으로 드러내며 0원으로 숨기지 않는다.
- 같은 목적지 계좌는 합산하며 월급계좌 몫은 보관으로 구분한다. 미배정액도 월급계좌에 남긴다. 흑자 계획에서는 배분표 합계가 월급과 정확히 일치한다. 적자 계획은 실행 가능한 표로 제시하지 않는다.
- 기존 잔액을 차감하지 않는 월급 한 번의 용도 배분이다. 계획 저장·수정은 실제 수입이나 이체 거래를 만들지 않는다.
- 월급 계획이 있으면 홈·목표·월급 화면 모두 연결 계좌의 배분 합계를 월 적립액으로 사용한다. 계획 삭제 시 목표에 직접 입력했던 월 적립액으로 돌아간다.
- 목표 필요액·도달일은 기존 0% 수익률 계산을 사용한다. 다른 목표의 초과 배분은 자동 재사용하지 않는다. 미등록 잔액·지출 계좌 연결·남은 납입일이 없는 목표가 있으면 전체 목표 부족액을 확정하지 않는다.
- 급여일은 1~31일이며 해당 날짜가 없는 달은 말일로 표시한다. 실제 은행의 주말·공휴일 급여 조정과 향후 인출·세금·수수료는 반영하지 않는다. 적금 상품 조건과 ISA·연금의 납입 한도를 자동 검증하는 기능은 없다.
- DB v4로 기존 v3 데이터를 보존하고 월급 계획을 리비전과 함께 원자적으로 저장한다. 백업 데이터 스키마는 v2이며 암호화 방식은 유지한다. v1 백업은 월급 계획 없는 v2로 검증·변환 후 복원한다. 계획 참조 계좌의 삭제·중복 배분·지출과 저축 계좌 중복을 막는다.
