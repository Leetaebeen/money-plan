# 개인 가계부 첫 구현

## 범위

목표 달성을 중심으로 홈·거래·목표·자산·백업 화면을 추가했다. React·Vite·Dexie를 유지하며 기존 계산기는 별도 메뉴에서 제공한다. 기본 계좌는 월급·고정비·생활비·청약·적금·ISA·연금저축의 역할만 제안하고 잔액은 비워둔다.

## 데이터와 계산

- DB v3: `accounts`, `ledgerEntries`, `ledgerGoals`, `importBatches`, `ledgerMeta` 추가. v1/v2 데이터는 유지한다.
- 시작 잔액은 기준일 00시 금액이다. 이후 실제 거래를 더해 잔액을 구한다. 모르는 잔액은 0으로 취급하지 않는다.
- 거래는 수입·지출·계좌 이동·환불·잔액 조정으로 나눈다. 순소비는 지출에서 환불을 차감하며 이체·잔액 조정은 제외한다.
- 직접 입력 이체는 두 계좌의 같은 날짜·반대 금액 거래로 원자적으로 저장하고 함께 수정·삭제한다. 파일로 가져온 이체는 계좌별 한쪽 기록으로 보존한다.
- 목표는 연결 계좌 전체 잔액을 사용하며 음수 잔액도 차감한다. 계좌를 두 목표에 중복 연결할 수 없다. 아직 등록하지 않은 계좌 잔액이 있으면 금액·도달일을 추정하지 않는다.
- 목표 필요액은 목표 잔액을 오늘 이후 목표일까지 남은 납입 회차로 나눠 원 단위 올림한다. 매월 납입일은 1~28일이다. 월 적립액은 계획값이며 실제 자산에 더하지 않는다. 투자 수익률은 0%다.
- 모든 원화 금액은 정수이며 입력 범위·합계의 안전한 정수 범위를 검증한다.
- 가계부 수정은 전역 리비전을 확인하는 DB 트랜잭션 안에서 검증·반영한다. 오래된 화면의 저장·복원은 실패하며 새로고침을 안내한다.

## 파일과 백업

- UTF-8/EUC-KR CSV 및 TSV 지원. 사용자 요청에 따라 Excel/XLSX 가져오기는 추가하지 않는다. PDF·은행별 양식 변환기는 미구현이다.
- 같은 파일 해시+계좌 조합은 재반영을 막는다. 날짜·금액·설명 기반 중복은 후보이며 사용자가 선택할 수 있다.
- 날짜 오류·미래 거래·기준일 이전 거래·0원·열 불일치·동시 입출금 등을 행 단위로 표시한다. 선택한 정상 행만 일괄 저장한다.
- 가져오기 취소는 해당 묶음의 수정된 거래까지 삭제한다. 원본 파일은 저장하지 않는다.
- 백업은 가계부 네 테이블의 데이터를 PBKDF2-SHA256 210,000회와 AES-256-GCM으로 암호화한다. 파일마다 난수 salt·IV를 사용한다.
- 복원은 인증 복호화와 스키마·관계 검증 후 미리보기를 제공한다. 확인하면 가계부만 원자적으로 교체하며 기존 계산기 이력은 유지한다.
- 백업에서도 계좌 기준일보다 이전 거래와 잘못된 계좌 식별자를 거부한다. 검증 실패 시 현재 가계부는 유지한다.
- 브라우저 내부 데이터는 별도 암호화되지 않는다. 동기화·서버 업로드는 없다.

## 검증

`npm run check`에 기존 테스트와 `apps/web/tests/ledger.test.ts`를 포함한다. 추가 테스트는 입력·달력, 잔액 범위, 목표 납입 회차, 1,000원 미만 목표 마무리, 목표 중복 연결, 이체 보존, CSV 인용/중복/오류, v2 업그레이드, 중복 파일, 원자적 롤백, 저장 충돌, 암호화 백업을 검증한다.

브라우저에서는 합성 계좌·목표 등록, CSV 정상/중복/오류 행 미리보기 및 반영, 암호화 백업 미리보기와 복원을 확인했다. 320px 및 390px 뷰포트를 검사했고 320px의 가로 넘침을 수정했다. 데스크톱의 좁은 뷰포트 검증은 iOS·Android 실기기 검증을 대신하지 않는다.

Windows 실행 환경에서 기존 출력 폴더를 처리하는 동안 빌드 프로세스가 종료되는 현상을 관찰했다. 새 출력 폴더를 사용하면 기본 압축 설정으로 정상 빌드된다. 기존 파일을 삭제할 필요 없이 아래처럼 별도 경로에서 검증할 수 있다. 재실행 시 새 폴더 이름을 사용한다.

```sh
node scripts/check-pwa-build.cjs apps/web/dist-pages-review

```

검사 스크립트의 경로 인자는 저장소 기준이며 생략하면 기존 `apps/web/dist`를 검사한다. CI의 기본 경로와 압축 설정은 유지한다.

## 후속 구현

월급 화면의 실적 조회 월까지 최근 6개월 수입·순소비·차이를 표시합니다. 전체 계좌의 수입·지출·환불만 집계하며 이체·잔액 조정과 오늘 이후 거래를 제외합니다. 이번 달은 오늘까지, 지난달은 월말까지 계산하고 환불은 수령한 달에 반영합니다. 수입·소비 기록이 없는 달은 0원 대신 기록 없음으로 표시합니다. 수입과 순소비의 차이는 실제 저축액이나 현재 잔액이 아니며 누락된 내역은 판별하지 않습니다. 2000년 이전 기간은 표시하지 않습니다.

2026-10-19 검증: 합성 급여 3,000,000원의 이번 달 반영과 이전 달 기록 없음 표시, 320px 화면에서 문서 가로 넘침 없이 표 영역 스크롤을 확인했습니다. 환불 초과·연도 경계·윤년·미래 거래·기록 없음·원본 보존을 포함해 전체 자동 테스트 165개가 통과했습니다.

월급 계획을 저장하면 이번 달의 계획·계좌 이름/역할·목표 연결을 함께 보관한다. 같은 달은 마지막 저장본으로 갱신하고 과거 달은 변경하지 않으며 최대 120개월을 보관한다. 기존 계획은 이번 달 보관 버튼으로 기록할 수 있고, 없는 과거 이력은 현재 계획으로 꾸며내지 않는다. 현재 계획이나 계좌·목표를 삭제/수정해도 보관 정보는 남는다. 실적은 현재 남아 있는 실제 거래로 다시 집계하므로 확정 결산이나 거래 자체의 복사본은 아니다. 삭제된 계좌나 불완전한 기록은 부족액을 미확정으로 표시한다. DB v7·백업 v5로 기존 만기 계획과 납부 연결을 보존하며 구버전은 월 이력이 없는 상태로 변환한다.

자산 화면에서 적금·저축 계좌의 만기일, 은행에서 확인한 예상 세후 총수령액, 이후 계좌별 배분과 메모를 관리한다. 예상액이 없으면 미배정액도 미확정이고, 초과 배분은 숨기지 않는다. 같은 계좌의 미수령 만기 계획은 하나만 허용한다. 30일 이내/오늘/만기일 경과를 표시하며 수령 확인은 사용자가 만기일 이후 오늘까지의 날짜로 직접 표시한다. 계획 저장·수령 확인·삭제는 실제 잔액·목표·거래를 바꾸지 않는다. 실제 수령은 거래 화면에서 기록하고 예상액을 현재 금융자산에 더하지 않는다. 금리·세금 계산, 자동 해지·송금, 조기 해지, ISA·연금의 만기 관리는 범위에 포함하지 않는다. 만기 이후까지 설정된 납부 일정과 월급 배분은 자동으로 없애지 않고 확인하도록 안내한다.

DB v6와 백업 v4는 만기 계획·배분·수령 확인을 저장한다. v3~v5 DB의 계좌·거래·월급 계획·납부 연결을 보존하며, v1~v3 백업은 만기 계획이 없는 v4로 변환한다. 일정/만기 계획에서 참조 중인 계좌 삭제를 막고, 전체 데이터 삭제 시 만기 계획도 제거한다.

월급 화면에 매월 고정비·계좌 이동 일정을 등록할 수 있다. 출금 계좌와 선택적 입금 계좌, 금액, 매월 1~31일, 시작/종료일을 저장하며 없는 날짜는 말일로 처리한다. 월별로 예정/오늘/기한 경과/거래 연결 상태와 미연결 지출·이체 합계를 나눠 보여준다. 미연결은 실제 미납의 확정이 아니다. 일정 등록만으로 실제 거래나 예산을 늘리지 않고, 실제 납부 확인 시 지출 또는 양쪽 이체를 원자적으로 생성하거나 금액·계좌가 일치하는 기존 거래를 연결한다. 같은 예정분의 재기록과 거래의 중복 연결을 막는다. 일치하는 같은 날 미연결 거래가 있으면 새 입력 대신 기존 거래 연결을 안내한다. 이체 연결은 상대 계좌가 확인되는 쌍만 허용하며 분할 납부는 미지원이다.

납부 연결 해제·일정 삭제는 실제 거래를 유지한다. 거래 삭제·가져오기 취소·금액/계좌/종류 변경으로 연결 조건이 깨지면 미연결로 돌아간다. 일정 변경은 기존 일정을 삭제하고 새로 등록한다. 자동 은행 송금·휴일 조정·알림·가용 현금 계산은 포함하지 않는다. DB v5로 월급 계획과 거래를 보존하며 일정을 추가했고, 백업 v3에는 일정과 납부 연결을 포함한다. v1/v2 백업은 일정이 없는 v3로 변환한다.

목표 화면의 조정안 비교는 해당 목표에 매달 더 모을 금액과 생활비 절감액을 입력해 현재/변경 가정의 달성일·납입 횟수·목표일까지의 월 부족액을 비교한다. 월급 계획의 미배정액, 기존 적자와 절감액을 함께 계산해 실행에 더 필요한 월 금액을 별도로 표시한다. 다른 목표 배분과 고정비·예비비는 가져다 쓰지 않는다. 월급 계획이 없으면 납입액별 예상일만 비교하고 재원 확보 여부는 미확정이다. 미등록 잔액·미래 잔액 기준일·월급/지출 계좌 연결·달성 완료 목표는 비교를 막는다. 수익률 0%와 오늘 이후 납입을 가정하며 저장 데이터나 실제 거래를 변경하지 않는다.

급여 주기 지출 예산은 예정 월급일 당일부터 다음 월급 전날까지의 고정비·생활비 계획과 오늘까지 기록한 지출·환불을 비교한다. 같은 계좌는 예산과 거래를 한 번만 합산하며, 별도 생활비 계좌에는 오늘을 포함한 남은 일수로 나눈 하루 기준액을 표시한다. 예산 초과는 숨기지 않고 하루 기준액은 0원으로 표시한다. 주기 중간에 기록을 시작한 계좌는 남은 예산을 확정하지 않는다. 잔액을 몰라도 전체 주기 거래 기록이 있으면 예산 비교는 가능하다. 환불은 수령일 주기에 반영하며 이전 소비와 자동 연결하지 않는다. 이는 현금 가용액이 아니며 예정 지출, 기록 누락, 다른 계좌 결제, 급여 입금 여부, 휴일 급여 조정은 반영하지 않는다. 계획 저장은 거래를 만들지 않는다.

월 저축 실적은 해당 월에 보관한 계획을 우선 사용한다. 이력이 없는 이번 달은 현재 계획을 비교하고, 과거 달은 계획/부족액을 미확정으로 표시한다. 초기 잔액·수입·평가손익은 제외하고, 출금은 실적을 줄이며 저축계좌 간 이동은 전체 합계에서 상쇄한다. 계좌별·목표별 부족액은 별도로 계산한다. 연결되지 않은 파일 이체나 불완전한 계좌 기록은 미확정으로 표시한다. 실제 거래 누락 여부 확인과 파일 이체의 상대 거래 연결은 후속 범위다.

CSV/TSV 가져오기는 제목 행 선택, 구분자 자동 감지·직접 지정, 양수 금액+입출금 구분 열을 지원한다. YYYYMMDD·점/슬래시 구분 날짜·한국어 날짜를 정규화하며 잘못된 일자와 시간·알 수 없는 입출금 구분·음수 방향 금액은 오류로 표시한다. 안내문·빈 행·인용된 여러 줄 내용 이후에도 미리보기의 행 번호는 원본의 실제 시작 줄을 가리킨다. 제목 선택은 처음 50개 행, 파일은 안내·빈 행 포함 5,050개 레코드, 거래는 5,000개, 열은 100개까지 허용한다. 실제 은행 파일로 검증한 전용 변환기는 아니며 XLSX/PDF 지원은 포함하지 않는다.

부채·순자산 원장, 카드 납부 연결, 급여 주기별 가용액, 적금 만기와 ISA·연금 입출금 관리는 아래 구현 기록에 반영되어 있다. 은행 자동 조회와 실기기 PWA 검증은 후속 작업이며, 기록된 순자산을 즉시 사용 가능한 돈으로 해석하지 않는다.

## 월급 배분 계획

- 월급 화면에 실수령액·급여일·고정비·생활비·매달 남길 예비비와 계좌별 저축·투자 배분액을 저장한다. 예비비는 이번 월급에서 남길 금액이며 이미 모은 비상금이 아니다.
- 배분 가능액 = 실수령액 - 고정비 - 생활비 - 예비비. 잔여액 = 배분 가능액 - 저축·투자 배분. 음수는 부족액으로 드러내며 0원으로 숨기지 않는다.
- 같은 목적지 계좌는 합산하며 월급계좌 몫은 보관으로 구분한다. 미배정액도 월급계좌에 남긴다. 흑자 계획에서는 배분표 합계가 월급과 정확히 일치한다. 적자 계획은 실행 가능한 표로 제시하지 않는다.
- 기존 잔액을 차감하지 않는 월급 한 번의 용도 배분이다. 계획 저장·수정은 실제 수입이나 이체 거래를 만들지 않는다.
- 월급 계획이 있으면 홈·목표·월급 화면 모두 연결 계좌의 배분 합계를 월 적립액으로 사용한다. 계획 삭제 시 목표에 직접 입력했던 월 적립액으로 돌아간다.
- 목표 필요액·도달일은 기존 0% 수익률 계산을 사용한다. 다른 목표의 초과 배분은 자동 재사용하지 않는다. 미등록 잔액·지출 계좌 연결·남은 납입일이 없는 목표가 있으면 전체 목표 부족액을 확정하지 않는다.
- 급여일은 1~31일이며 해당 날짜가 없는 달은 말일로 표시한다. 실제 은행의 주말·공휴일 급여 조정과 향후 인출·세금·수수료는 반영하지 않는다. 적금 상품 조건과 ISA·연금의 납입 한도를 자동 검증하는 기능은 없다.
- DB v4로 기존 v3 데이터를 보존하고 월급 계획을 리비전과 함께 원자적으로 저장한다. 백업 데이터 스키마는 v2이며 암호화 방식은 유지한다. v1 백업은 월급 계획 없는 v2로 검증·변환 후 복원한다. 계획 참조 계좌의 삭제·중복 배분·지출과 저축 계좌 중복을 막는다.

### 카드·대출과 순자산

- 자산 화면에서 신용카드·대출 계좌를 추가할 수 있습니다. 기준일의 카드 미결제액과 대출 원금은 음수로 입력합니다 (30만 원이면 `-300000`). 초과 납부로 양수인 잔액은 자산으로 표시합니다.
- 카드 사용은 카드 계좌의 지출, 취소 환불은 환불로 기록합니다. 은행에서 카드로 결제대금을 보내거나 대출 원금을 갚을 때는 **계좌 이동**으로 기록합니다. 대출 실행은 대출 계좌에서 은행 계좌로 이동합니다. 이자와 수수료는 별도 지출입니다.
- 홈은 등록된 양수 잔액의 합인 자산, 음수 잔액의 절댓값 합인 부채, 그 차이인 순자산을 표시합니다. 미등록 잔액은 합계에서 제외하며 미확인 계좌 수를 표시합니다.
- 기존 카드대금이 지출로 기록되어 있다면 직접 계좌 이동으로 수정해야 합니다. 중복 기록을 자동 추정하거나 삭제하지 않습니다.
- 카드·대출은 저축 목표나 월급·생활비 보관 계좌로 선택할 수 없습니다. 거래 입력·수정에서 카드 지출과 환불을 고정비 또는 생활비 예산으로 분류하면 급여 주기 예산에 합산합니다. 미분류 거래, 연결할 예산 계좌 누락, 주기 중간부터 시작하는 카드 기록이 있으면 남은 예산·하루 기준액을 표시하지 않습니다. 홈의 월 소비에는 카드 사용과 환불이 포함됩니다.
- 월급 화면에서 카드 청구액 1회 납부 또는 앞으로 낼 할부 총액의 1~36회 균등 납부 일정을 등록할 수 있습니다. 실제 청구액을 직접 확인해 입력하며 이자·수수료·휴일은 자동 계산하지 않습니다. 기존 예정 이체 기능으로 원금 상환 일정도 등록할 수 있습니다.
- 백업 형식은 7입니다. 기존 1~6 백업을 읽으며, 버전 5~6의 월별 계획 이력도 보존합니다. 카드 소비 예산 구분은 암호화 백업에 포함되며, 기존 미분류 거래는 임의로 분류하지 않습니다. 저장소 테이블 구조는 변경하지 않습니다.

카드 예산은 사용·환불을 기록한 날짜를 기준으로 반영하며 결제일 기준이 아닙니다. 환불은 원래 사용과 동일한 예산으로 선택하세요. 현재 월급 계획의 고정비·생활비 계좌를 연결 대상으로 사용합니다. 두 예산의 계좌가 같으면 합산하되 하루 생활비는 계산하지 않습니다.


### 카드 결제 예정액·할부 일정

- 카드와 결제 계좌, 앞으로 낼 총액, 남은 납부 횟수, 첫 결제일을 입력하면 저장 전에 회차별 예정액을 확인할 수 있습니다. 첫 결제일의 일자를 매월 사용하고 없는 날짜는 월말로 맞춥니다. 총액을 원 단위로 나눈 나머지는 마지막 회차에 반영합니다.
- 각 회차는 종료일이 있는 1회성 계좌 이동 일정으로 저장합니다. 일정 한도 100개 내에서 등록하며, 초과 시 전체 등록을 취소합니다. 기존 저장소·백업 형식을 그대로 사용합니다.
- 같은 카드의 같은 월에 결제 일정이 있으면 새 카드 일정 등록을 거부합니다. 여러 할부나 일시불이 함께 청구되면 카드사의 월 청구 총액으로 관리하세요. 일반 일정 추가를 통한 수동 중복은 자동 정리하지 않습니다.
- 아래 납부 일정에서 월별 카드 예정액·거래 미연결 합계를 확인하고 실제 납부 거래를 연결합니다. 미연결은 미납을 뜻하지 않습니다. 청구액이나 결제일이 변경되면 해당 회차의 예정 금액·날짜 수정 버튼으로 변경하세요. 연결된 납부 거래가 있으면 먼저 연결을 해제해야 하며 실제 거래는 별도로 수정합니다. 선택한 회차만 변경되고 다른 회차의 금액은 재분배하지 않습니다. 일정 삭제는 실제 거래를 삭제하지 않습니다.
- 할부 구매는 전체 구매액을 구매일의 카드 지출로 한 번 기록합니다. 결제 일정 등록 자체는 소비·부채를 추가하지 않으며 실제 결제는 은행에서 카드로의 계좌 이동입니다. 자동 청구서 조회, 복수 할부의 자동 합산, 카드 이자 계산은 지원하지 않습니다.


### 홈의 30일 납부 준비

오늘부터 30일(오늘 포함) 동안 거래가 연결되지 않은 카드·고정비·적금 일정을 결제 계좌별로 합산합니다. 월급·고정비·생활비 계좌는 오늘까지의 등록 잔액과 비교해 부족액을 표시하고, 음수 잔액이면 그 부족분도 준비 금액에 더합니다. 적금·투자·카드·대출 계좌와 미등록 잔액은 사용 가능한 현금으로 가정하지 않습니다. 예정 입금이나 다른 계좌에서 받을 예정 이체는 미리 더하지 않습니다.

이번 달 예정일이 지난 미연결 일정은 별도 건수로 안내하며 30일 예정액에는 포함하지 않습니다. 지난달 이전 내역은 월별 일정 화면에서 확인합니다. 미연결이 실제 미납을 의미하지 않으므로 이미 납부한 거래를 먼저 연결해야 합니다. 등록되지 않은 미래 소비나 이자·수수료까지 보장하는 현금 예측은 아닙니다.

홈의 개별 납부 일정을 누르면 해당 월·결제 계좌·카드의 미연결 일정으로 바로 이동합니다. 월별 일정에서 계좌·카드·연결 상태 필터를 조합할 수 있고 합계는 표시 중인 일정만 집계합니다. 필터 초기화는 조회 월을 유지하며 전체 상태로 돌아갑니다.


### 복원 전 데이터 비교

복원 미리보기에서 계좌·거래·목표·납부 일정·만기 계획·월별 계획·가져오기 이력의 현재/백업 개수와 추가·변경·제외 건수를 표시합니다. 같은 식별자의 내용 변경도 확인하며 월급 배분 계획의 변경 여부를 별도로 안내합니다. 복원은 전체 교체입니다. 현재 데이터 먼저 백업 버튼은 암호화 파일 다운로드를 요청하며 실제 저장 완료는 사용자가 확인합니다. 미리보기 이후 현재 저장 버전이 변경되면 복원을 비활성화하고 다시 확인하도록 안내합니다. 다른 탭의 변경은 저장 시 기존 버전 검사로 보호합니다.


### 카테고리별 소비

거래 화면에서 선택한 월·계좌의 전체 기록을 기준으로 지출, 환불, 환불 차감 소비를 집계합니다. 거래 목록의 30건 페이지와 관계없이 오늘까지의 지출·환불을 모두 포함하며, 이체·수입·잔액 조정은 제외합니다. 환불만 있는 카테고리는 음수 소비를 유지합니다. 카테고리를 누르면 해당 지출·환불 목록으로 좁혀지고 월이나 계좌 변경 시 카테고리 필터가 해제됩니다. 요약 합계는 카테고리 필터와 무관하게 선택한 월·계좌 기준을 유지합니다.


거래 검색은 설명(가맹점·메모)과 카테고리에서 공백으로 나눈 단어를 모두 포함하는 내역을 찾습니다. 영문 대소문자와 전각/반각 차이를 정규화하며 월·계좌·거래 종류 필터를 함께 적용합니다. 소비 요약도 검색·종류 조건에 맞는 기록만 집계하므로 지출만 선택하면 환불은 합계에서 제외됩니다. 필터 초기화는 조회 월을 유지합니다.


### 최근 6개월 순자산 추이

자산 화면에서 현재 등록한 계좌의 월말 자산·부채·순자산과 전월 대비 변화를 확인합니다. 이번 달은 오늘까지 집계하고 미래 거래는 제외합니다. 과거 월에 기준 잔액이 없거나 계좌 기준일 이전이면 전체 합계와 전월 비교를 보류합니다. 현재 계좌와 거래로 다시 계산하므로 계좌 삭제나 과거 내역 변경에 따라 과거 추이도 바뀝니다. 자산 평가액은 입력한 조정 거래만 반영하며 전월 대비는 투자 수익률이 아닙니다.

거래 목록은 30건씩 표시하며 처음·이전·다음·마지막 페이지로 이동할 수 있습니다. 마지막 거래 삭제나 가져오기 되돌리기로 페이지 수가 줄면 남아 있는 마지막 페이지로 보정합니다. 페이지 이동 시 거래 목록에 초점을 옮기며 표시 범위를 안내합니다.

중복 의심 거래 필터는 전체 기록에서 같은 계좌·날짜·종류·금액·설명을 가진 수입·지출·환불을 표시합니다. 설명의 공백·영문 대소문자·전각 차이는 정규화하고 카테고리 차이는 무시합니다. 같은 날 실제 반복 결제일 수 있어 자동 삭제하지 않으며, 이체와 잔액 조정은 검사하지 않습니다. 의심 건수는 중복 그룹의 모든 거래를 포함합니다.

거래 화면에서 현재 페이지의 지출·환불을 최대 30건 선택해 카테고리를 일괄 변경할 수 있습니다. 선택한 거래의 카테고리만 변경하며 금액·계좌·카드 소비 예산 구분과 가져오기 이력은 유지됩니다. 검색·필터·페이지 변경 시 선택을 해제하고, 저장 시 누락되거나 종류가 바뀐 거래가 있으면 전체 변경을 취소합니다.

## 구매 전 비교와 수입 중단 시뮬레이션
