# Money Plan

계좌와 실제 거래를 정리하고 목표 금액까지 필요한 저축을 계획하는 개인 가계부 PWA입니다.

홈에서 등록된 금융자산, 월 수입·순소비와 목표 진행률을 확인합니다. 계좌 기준 잔액, 실제 거래, 계좌 간 이체, 목표를 기기에 저장하며 CSV/TSV 파일의 열을 확인한 뒤 거래를 가져올 수 있습니다. 백업은 암호화 파일로 내보내고 미리보기 후 복원합니다. 은행 자동 연동, 은행별 XLSX/PDF 양식, 부채·카드청구 원장은 아직 지원하지 않습니다.

기존 월급·여윳돈 계산기는 `이전 월급 계산기` 메뉴에 유지했습니다. 기존 프로필·초안·계획 이력은 DB 업그레이드 시 보존하며 새 가계부의 실제 거래로 변환하지 않습니다. 입력을 저장하지 않는 공개 월급 계산기도 별도 정적 페이지로 제공합니다. 엔진은 특정 은행 상품, ETF, 종목, 매수 시점이나 예상수익률을 출력하지 않습니다.

## 가계부 시작하기

1. **자산**에서 계좌 이름·역할과 기준일 00시 잔액을 입력합니다. 잔액을 비워두면 미등록으로 표시합니다. 이전 거래를 가져올 때 현재 잔액을 시작 잔액으로 입력하지 않습니다.
2. **거래**에서 실제 거래를 직접 입력하거나 CSV/TSV를 가져옵니다. 안내문이 있으면 처음 50개 행 중 제목 행을 선택합니다. 금액 형식은 부호 있는 한 열, 입금·출금 두 열, 양수 금액과 입출금 구분 열을 지원합니다. 날짜·내용·금액 열을 선택하고 중복 후보·오류를 확인한 뒤 선택한 행만 반영합니다. 구분자 자동 감지가 맞지 않으면 쉼표·탭을 지정하고 파일을 다시 선택합니다.
3. 내 계좌 사이의 이동은 **계좌 이동**으로 분류합니다. 직접 입력한 이체는 두 계좌에 함께 기록됩니다. 가져온 거래는 각 계좌의 한쪽 기록이므로 상대 계좌 내역도 따로 반영합니다.
4. **목표**에서 금액·날짜·월 적립액·납입일을 입력하고 목표에 쓸 계좌를 연결합니다. 한 계좌는 한 목표에만 연결되며 전체 잔액을 사용합니다. 수익률 0%, 오늘 이후 납입 회차 기준으로 계산합니다.
5. **월급**에서 실수령액·급여일·고정비·생활비·매달 남길 비상 예비비를 입력하고 적금·청약·ISA·연금 계좌의 월 배분액을 설정합니다. 같은 계좌로 갈 돈은 합산하고, 예산 초과와 목표별 추가 필요액을 보여줍니다. 계획을 저장해도 실제 잔액·거래는 바뀌지 않습니다. 월급 계획이 있으면 목표의 월 적립액은 연결 계좌 배분액을 사용합니다.
6. **백업**에서 8자 이상 암호로 계좌·거래·목표·월급 계획을 보관합니다. 복원 전 데이터 개수와 월급 계획 포함 여부를 확인하고 현재 가계부를 교체합니다. 이전 버전 백업도 복원할 수 있으며 월급 계획이 없는 백업은 현재 월급 계획을 지웁니다. 암호 분실 시 복구할 수 없습니다. 이전 계산기 이력은 해당 메뉴에서 별도로 내보냅니다.

가져오기는 UTF-8/EUC-KR CSV 및 탭으로 구분된 TSV, 파일당 5MB·5,000행, 전체 25,000거래까지 지원합니다. 원본 파일은 저장하지 않고 파일 해시와 검토한 거래만 보관합니다. 날짜·내용·금액이 같은 거래는 자동 삭제하지 않고 중복 후보로 표시합니다. 이력에서 가져온 묶음을 되돌릴 수 있습니다. 실제 개인 내역은 Git에 추가하지 않습니다.

데이터 모델·검증 범위·다음 단계는 [가계부 구현 노트](docs/personal-ledger.md)를 참고하세요.

금융감독원 금융상품 한눈에의 공식 예·적금 정보를 수집하는 Node 패키지와, 출처·공시월·수집시각을 함께 보여주는 금융상품 사실조회 화면을 제공합니다. 금리 순위나 상품 추천은 제공하지 않습니다.

## 테스트

Node.js 24 이상에서 실행할 수 있습니다.

```bash
npm install
npm run dev:web
```

전체 보안 검사, 타입 검사, 테스트, 프로덕션 빌드는 다음 명령으로 확인합니다.

```bash
npm run check
npm test
```

금융상품 한눈에 인증키를 서버 환경변수로 설정하면 정기예금·적금 공식정보를 JSON으로 수집할 수 있습니다. 인증키가 브라우저 번들에 들어가지 않도록 웹앱에서는 이 명령을 호출하지 않습니다.

```powershell
$env:FINLIFE_API_KEY = "<발급받은_인증키>"
npm run collect:finlife -- --kind all --group 020000 --output apps/web/public/data/financial-products.json
```

GitHub Pages 배포에서 공식정보를 자동 갱신하려면 저장소의 `Settings` →
`Secrets and variables` → `Actions`에 `FINLIFE_API_KEY`라는 Repository secret을
등록합니다. 키가 있으면 `main` 배포 전에 새 스냅샷을 수집하고, 매주 월요일
오전 9시 15분(KST)에도 같은 검증·배포를 실행합니다. 정기·수동 실행은 키가
없거나 수집 검증이 실패하면 현재 배포를 유지한 채 실패합니다.

계좌·거래·목표와 기존 계산기 데이터는 브라우저 IndexedDB에만 저장합니다. 다운로드 백업만 암호화하며 브라우저의 데이터 자체를 별도 암호화하는 기능은 아닙니다. 회원가입·기기 간 동기화·개인 금융정보 서버 전송은 사용하지 않습니다.

## 무료 배포

`main` 브랜치의 CI 검증이 끝나면 GitHub Pages용 PWA를 빌드하고 자동 배포합니다.

- 공개 주소: <https://leetaebeen.github.io/money-plan/>
- 저장 없는 공개 계산기: <https://leetaebeen.github.io/money-plan/calculator/>
- 배포 빌드: `npm run build:pages`
- 배포 산출물 검사: `npm run check:pages`

첫 배포 전에 저장소의 `Settings` → `Pages` → `Build and deployment`에서 `Source`를 `GitHub Actions`로 한 번 선택해야 할 수 있습니다. API 키는 필요하지 않습니다.

## 금융상품 갱신 결과 확인

Actions의 CI 실행 요약에서 생성시각·상품 수·공시월을 확인하고,
Artifacts의 `financial-products-실행번호-재실행번호`에서 30일간 JSON을 받을 수 있습니다.
수집 직후 빈 상품 또는 생성 후 1시간을 넘긴 데이터는 배포를 중단합니다.
수집·검증 실패 시 해당 실행 요약과 실패 단계의 로그에서 원인을 확인합니다.
아티팩트 보관은 수집 이력이며 최종 배포 성공 여부는 `deploy-pages`에서 확인합니다.
