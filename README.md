# 머니플랜

월급 배분과 거래 기록을 바탕으로 자산 목표를 관리하는 개인 가계부입니다.

## 현재 기능

- 홈: 순자산, 수입·소비, 앞으로 30일 납부 일정
- 구매 전 비교: 선택 계좌의 잔액·예산 및 연결 목표의 달성일 변화
- 수입 중단 시뮬레이션: 사용할 현금·저축에서 부채와 보호할 돈을 빼고 월 지출로 나눈 생활 가능 기간
- 월급: 계좌별 배분, 월급 주기 예산, 계획 이력과 실제 저축 비교
- 거래: 수입·지출·환급·이체·잔액 조정, 검색·분류, CSV/TSV 가져오기
- 목표: 진행률, 월 필요 저축액, 목표 달성 시뮬레이션
- 자산: 계좌·부채, 잔액 맞추기, 월별 추이, 적금 만기, ISA·연금 납입 기록
- 백업: 암호화 파일 내보내기·검사·전체 복원

이전 월급 계산기, 저장 없는 간편 계산기, 금융상품 공시 화면은 제거했습니다.
금융상품 API 자동 수집과 정기 갱신도 실행하지 않습니다. 현재 앱에는 API 키가 필요 없습니다.

## 저장과 연결

가계부 기록은 이 브라우저의 IndexedDB에 저장됩니다. 로그인, 서버 저장, 기기 간 자동 동기화는 없습니다.
백업 파일만 암호화하며 기기 내부 데이터 자체를 별도 암호화하지 않습니다.

서비스 워커를 이용한 오프라인 저장·실행은 제거했습니다. 앱을 열 때 인터넷 연결이 필요합니다.
기존 설치의 캐시는 온라인 재방문 시 해제합니다. `public/sw.js`는 이전 서비스 워커를 해제하기 위한 전환 파일이며,
새 오프라인 캐시를 만들거나 요청을 가로채지 않습니다. 기존 가계부 데이터는 지우지 않습니다.
과거 계산기의 DB 구조·호환 모델은 기존 저장소를 안전하게 유지하기 위해 남겨두었습니다.

## 실행·검증

Node.js 24 이상:

```bash
npm ci --ignore-scripts --audit=false
npm run dev:web
npm run check
npm run build:pages
npm run check:pages
```

`npm run setup:git`으로 커밋·푸시 검사를 설치할 수 있습니다.
Git 작성자 이메일은 본인의 GitHub noreply 주소를 사용합니다.

## 배포

`main` 변경은 CI 검증 후 GitHub Pages에 배포합니다.
변경은 임시 브랜치에서 PR을 만들고 GitHub Actions의 필수 `verify` 검사를 통과한 뒤 병합합니다.
`verify`는 일반 웹 빌드뿐 아니라 `/money-plan/` 배포 경로와 보안 정책도 검사합니다.
최신 main 기준 검사가 필요하며 병합한 임시 브랜치는 자동 삭제합니다. 병합 후 로컬 main은 `git pull --ff-only`로 갱신합니다.

- 사이트: https://leetaebeen.github.io/money-plan/
- Pages Source: GitHub Actions
- 오프라인 캐시 해제 검증: `npm run check:web`

`docs/`의 기존 개발 기록 중 계산기·공시·PWA 관련 설명은 제거 이전의 이력입니다.
현재 제공 범위는 이 문서를 기준으로 합니다.

## 보안 운영

- `npm run security:audit`는 개발 의존성을 포함한 알려진 취약점을 검사합니다. CI는 낮음 이상 취약점에도 실패하며 매주 재검사합니다.
- GitHub Actions는 커밋 SHA로 고정하고 Dependabot이 npm 및 Actions 업데이트를 제안합니다. Dependabot PR을 병합할 때 저장소 커밋 형식에 맞게 squash 메시지를 작성합니다.
- 운영 빌드에는 외부·인라인 스크립트를 제한하는 CSP와 referrer 차단 메타 태그를 넣습니다. iframe 안에서는 가계부 화면을 렌더링하지 않습니다.
- GitHub Pages에서는 임의의 응답 헤더를 설정할 수 없습니다. 메타 CSP와 화면 렌더링 차단은 서버의 `frame-ancestors`/`X-Frame-Options`를 완전히 대체하지 않습니다. 개발·미리보기 서버는 별도 보안 헤더를 설정합니다.
- 브라우저 IndexedDB는 평문입니다. 백업 암호화가 기기 내부 저장소까지 암호화하지는 않으므로 기기·브라우저 프로필 접근 권한을 관리해야 합니다.
- 푸시 전과 CI에서 업로드할 커밋의 파일 및 메시지를 검사합니다. 중간 커밋에 키를 넣었다가 지워도 과거 버전에서 감지하면 차단합니다. 새 브랜치는 전체 도달 가능한 이력을 검사합니다.
- 이 검사는 알려진 패턴 기반입니다. 바이너리 내용·서브모듈 내부는 검사하지 않으며 5 MiB 초과 파일은 안전하게 차단합니다. 모든 개인정보나 비밀값의 부재를 보증하지 않습니다. 로컬 훅은 우회될 수 있어 서버의 필수 검사 설정을 대체하지 않습니다.
